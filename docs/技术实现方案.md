## 1. 引言

### 1.1 文档目的

本文档旨在详细描述FaceGuard人脸识别管理系统的技术实现方案，作为项目开发的核心技术指导文档。文档从项目定位出发，阐述技术选型依据、详细设计思路、核心算法原理及关键技术实现，为开发团队提供具体的技术实现指导，同时为项目评审和后续迭代提供技术支撑。

本文档遵循"倒推法"编写原则，即基于项目最终落地实现的功能和技术栈，反向推导设计思路和技术决策过程，阐明每个技术选型背后的考量因素，确保文档具有可追溯性和说服力。

### 1.2 项目概述

FaceGuard是一款面向中小企业、教育机构、园区等场景的轻量化人脸识别身份管理系统。系统采用Python语言开发，结合Django Web框架和OpenCV计算机视觉库实现完整的人脸识别功能。系统采用B/S架构，用户通过浏览器即可完成用户注册、人脸录入、人脸识别登录、管理员管理等全部功能，无需安装专用客户端软件。

项目设计开发周期约为4个月，技术栈的选择充分考虑了项目实际应用场景的需求、开发成本和周期的约束，以及技术成熟度和团队技术储备，力求在技术先进性和可行性之间取得平衡。

### 2.2 后端语言选型：Python

**倒推分析**：项目最终采用Python作为后端开发语言，这一选择基于以下考量因素。

Python在计算机视觉领域的生态最为丰富，OpenCV、scikit-image、Pillow等图像处理库均以Python为主要接口语言。若选用Java或Go等其他语言，虽然也能调用OpenCV，但API封装程度和社区资源丰富度均不及Python原生接口。此外，Python语法简洁，适合快速原型开发，能够显著缩短项目开发周期。

对于毕业设计等教学目标导向的项目，Python的可读性有利于代码审查和项目讲解，而其丰富的库资源也能帮助开发者快速解决各类技术问题。

### 2.3 Web框架选型：Django

**倒推分析**：项目最终采用Django作为Web框架，这一选择基于以下考量因素。

首先，Django提供了完善的MTV（Model-Template-View）架构模式，将数据模型、业务逻辑和页面呈现进行了清晰的分层，符合Web开发最佳实践。其次，Django内置了强大的ORM系统，能够通过Python对象操作数据库表，大幅减少SQL编写量，降低SQL注入风险。再次，Django提供了开箱即用的用户认证、会话管理、CSRF防护等安全功能，这些正是人脸识别系统所需的基础安全能力。

相比Flask等轻量级框架，Django的"约定优于配置"理念更适合快速开发，其内置的管理后台功能也能加速项目原型验证阶段的迭代。

### 2.4 计算机视觉库选型：OpenCV

**倒推分析**：项目最终采用OpenCV实现人脸检测和识别功能，这一选择基于以下考量因素。

OpenCV是计算机视觉领域最成熟的开源库，拥有超过2500种优化算法，其中人脸检测和识别相关算法经过了学术界和工业界的广泛验证。OpenCV提供了Python接口（cv2模块），安装便捷，API设计清晰。

在人脸检测方面，项目采用了OpenCV内置的Haar级联分类器算法，该算法无需额外训练模型，直接加载预训练好的分类器文件即可使用，部署简单。在人脸识别方面，项目采用了LBPH（Local Binary Patterns Histogram）算法，这是OpenCV支持的三种人脸识别算法中最适合自建模型场景的一种，算法原理清晰，便于理解和调试。

### 2.5 数据库选型：MySQL

**倒推分析**：项目最终采用MySQL作为关系数据库，这一选择基于以下考量因素。

MySQL是开源关系型数据库的事实标准之一，拥有成熟的存储引擎体系和完善的索引机制。项目的用户规模预估在百人级别，数据量较小，MySQL的性能完全能够满足需求。

相比SQLite等嵌入式数据库，MySQL支持真正的多用户并发访问，适合未来扩展为多实例部署场景。相比PostgreSQL，MySQL在Windows平台的兼容性更好，XAMPP等一键部署方案成熟，降低了开发和部署的复杂度。

### 2.6 前端技术选型：原生HTML/CSS/JavaScript

**倒推分析**：项目最终采用原生HTML/CSS/JavaScript实现前端页面，这一选择基于以下考量因素。

项目的核心交互逻辑集中在用户注册、人脸采集、登录等少数页面，页面数量有限，不存在复杂的单页应用场景。使用原生技术无需引入Webpack等构建工具，项目的文件结构更加简洁，开发者能够专注于业务逻辑实现而非工具链配置。

对于摄像头调用这一核心功能，现代浏览器提供的MediaDevices API已经能够满足需求，配合Canvas API进行图像截取和Base64编码，无需引入第三方图像处理库。

#### 5.1.2 密码安全设计

用户密码采用SHA-256算法进行哈希处理后存储，数据库中不存储明文密码。注册时，前端将用户输入的密码直接传输到后端，后端在保存前执行哈希运算。

```
"123456"     "8d969eef6e..."  加密后字符串
```

### 5.2 人脸识别功能设计

#### 5.2.1 技术原理：Haar级联分类器人脸检测

Haar级联分类器是基于Viola-Jones框架的人脸检测算法，其核心思想是通过大量正样本（包含人脸的图像）和负样本（不包含人脸的图像）训练得到一系列弱分类器，再将这些弱分类器级联组合成强分类器，最终实现对人脸区域的高速准确检测。

**算法优势**：

- 检测速度快，能够满足实时视频流处理需求
- 模型文件体积小，移植部署方便
- 对正面人脸检测效果好，误检率可控

**在本项目中的应用**：OpenCV提供了预训练好的Haar级联分类器模型文件（haarcascade\_frontalface\_default.xml），项目直接加载使用，无需自行训练模型。

```
输入图像 ────▶ 灰度转换 ────▶ 直方图均衡化 ────▶ 级联分类器检测 ────▶ 输出人脸区域
(RGB图像)       (提高对比度)     (光照补偿)        (多尺度扫描)
```

#### 5.2.2 技术原理：LBPH人脸识别算法

LBPH（Local Binary Patterns Histogram，局部二值模式直方图）是一种基于纹理特征的人脸识别算法。其核心思想是将图像划分为若干小块，对每个像素与其邻域像素进行比较，得到局部二值模式，再统计每块的直方图特征进行匹配。

**算法步骤**：

| 步骤 | 操作       | 说明                                      |
| -- | -------- | --------------------------------------- |
| 1  | 局部二值模式编码 | 对每个像素与其8邻域进行比较，大于中心像素标记为1，否则为0，得到8位二进制数 |
| 2  | 特征图构建    | 将每个像素的二进制值转换为中心像素的新灰度值，构建LBP特征图         |
| 3  | 图像分块     | 将LBP特征图划分为若干小区域（如4×4块）                  |
| 4  | 直方图统计    | 统计每个小区域的灰度直方图                           |
| 5  | 特征向量拼接   | 将所有小区域的直方图首尾拼接，形成最终的特征向量                |
| 6  | 相似度匹配    | 待识别图像采用相同流程生成特征向量，与底库特征向量逐一比较，计算相似度     |

**算法优势**：

- 对光照变化具有较好的鲁棒性
- 算法原理清晰，便于理解和调试
- 支持增量训练，新增用户无需重新训练全部样本

**在本项目中的应用**：用户通过 `POST /face/register` 录入样本后，`register_face_from_base64()` 保存 PGM 灰度图并**立即调用 `_retrain()`** 全量训练，产出 `lbph_model.yml` 与 `label_map.json`。识别时 `recognize_face_login()` 对单张登录图执行 `predict`，将 `confidence` 换算为 0～100 分并与 `face_threshold`（默认 70）比较。陌生人场景可调用 `match_all_registered_faces()` 遍历比对。

## 8. 安全设计

### 8.1 密码安全

| 设计项  | 实现方式            |
| ---- | --------------- |
| 存储加密 | SHA-256哈希算法，不可逆 |
| 传输安全 | HTTPS加密传输（生产环境） |
| 强度校验 | 最少6位字符          |

### 8.2 会话安全

| 设计项         | 实现方式                  |
| ----------- | --------------------- |
| Session存储   | 服务端存储，客户端仅保存SessionID |
| Cookie安全    | HttpOnly标志防止XSS读取     |
| 超时机制        | 30分钟无活动自动失效           |
| Session固定防护 | 登录成功后重新生成SessionID    |

### 8.3 权限控制

系统采用基于角色的访问控制（RBAC）模型：

| 角色         | 权限范围                                 |
| ---------- | ------------------------------------ |
| 普通用户（user） | 管理个人信息、管理本人人脸数据、使用系统功能               |
| 管理员（admin） | 普通用户全部权限 + 用户管理 + 日志审计 + 安全告警 + 参数配置 |

### 8.4 SQL注入防护

Django ORM采用参数化查询机制，自动防止SQL注入攻击：

```python
# Django ORM自动进行参数化查询
user = User.objects.filter(username=username, password=password).first()
# 生成的SQL: SELECT * FROM users WHERE username = ? AND password = ?
```

### 8.5 XSS防护

Django模板引擎默认对变量进行HTML转义，防止XSS攻击：

```html
<!-- Django模板自动转义 -->
{{ user.username }}  <!-- 如果username为<script>alert(1)</script>，会渲染为转义后的字符串 -->
```
